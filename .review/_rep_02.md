## 2. Critical findings (🔴)

Grouped by the kind of harm. "Source" names the raw report (`01`…`08`, `04b`, `crit`) holding the full evidence; 🔒 marks security findings. IDs were renumbered after the verification pass — Appendix E maps them to the IDs used in the raw and verification files.

### 2.1 Security boundaries that do not hold

**C1. Tool bodies drop the agent-identity contextvar, so the per-agent connector grant check is silently bypassed** 🔒 — `src/gaia/agents/base/agent.py:3157-3186` (`_call_tool_bounded`) spawns a bare `threading.Thread`; Python threads start with an empty context, so inside any tool `current_agent_id()` is `None`, and `src/gaia/connectors/api.py:187-197` / `handler.py:152-155` treat `None` as "skip the per-agent grant check". Every tool executed through the agent loop since #1591 has run with the #915 grant control dead. Today's in-tree callers pass `agent_id=` explicitly (email agent, daemon forward), but the documented public pattern for skills (`docs/sdk/infrastructure/connectors.mdx:257-262`) is the ungated one. *Probe:* main thread sees `gaia/probe`, tool body sees `agent_id: None`. Related but independent: the Tavily key (`web/tavily.py:125,145` → `connectors/handler.py:137-168`) passes neither `agent_id` nor `required_scopes`, so it stays ungated **even after this fix** (`test_handler.py:161 test_no_agent_id_skips_grant_check` locks it in) — see I14. **Fix:** take `ctx = contextvars.copy_context()` in the *caller* thread and run `Thread(target=lambda: ctx.run(_target))` (copying inside `_target` is a no-op); make `_authorize_access` (`api.py:167`) and `get_credential` (`handler.py:133`) fail closed when identity is absent while an agent runtime is active; update `connectors.mdx:257-262`, which teaches the pattern fail-closed will reject; add a test that executes a tool via `_execute_tool` and reads `current_agent_id()`. Must land together with C17 (the ledger it checks can otherwise be set to arbitrary scopes). Confidence High. Tracked: none. Source 01, 03, crit.

**C2. `notify_desktop` builds a PowerShell command by string-interpolating model-controlled text → command injection on Windows** 🔒 — `hub/agents/chat/python/gaia_agent_chat/agent.py:1643-1701`. `plyer` is not a declared dependency (`grep plyer setup.py` → none), so the `powershell -Command "...::Show('{message}', '{title}')"` fallback is the only path on every Windows install; a single quote breaks out; the tool is not in `TOOLS_REQUIRING_CONFIRMATION`; registered in every non-"chat" profile of the flagship; window hidden, output to `DEVNULL`. *Probe:* `message="hi'); Write-Host INJECTED; ('x"` renders to `...::Show('hi'); Write-Host INJECTED; ('x', 't')`. Attacker position: prompt-injected content steering a tool argument; no click. **Fix:** pass strings as arguments to a fixed script block (or `-EncodedCommand` with escaped literals), gate behind confirmation, add a quote-injection test. Confidence High. Tracked: none. Source 01.

**C3. PowerShell command injection via a document *filename* — no model, no confirmation** 🔒 — `src/gaia/rag/pptx_utils.py:313-336` (`convert_pptx_to_pdf`, reached from `rag/sdk.py:1048`) f-string-interpolates the absolute file path into a single-quoted PowerShell literal and runs `powershell -NoProfile -Command`; `_sanitize_stem` (`ui/routers/documents.py:123`) strips `<>:"/\|?*` but not `'`. A deck named `quarterly'; Start-Process calc; '.pptx` uploaded through the Agent UI documents endpoint executes on **indexing** — no tool call, no model decision, no modal. Same class as C2 with strictly fewer preconditions. **Fix:** pass paths as `-args` to a `param($in,$out)` script block or `-EncodedCommand`; reject `'` in `_sanitize_stem`; quote-in-filename test. Confidence High. Tracked: none. Source crit (found in a file the review had listed as unread).

**C4. Windows shell "read-only allowlist" is bypassable — arbitrary command execution via `cmd.exe`, and file writes through allowlisted `git`/`wmic`** 🔒 — `src/gaia/agents/tools/shell_tools.py:192-194` flags `&` only when followed by whitespace (`&(?=\s|$)`), and on Windows the validated *string* is handed to `cmd.exe` with `shell=True` (`:949-958, :1029`). The PowerShell filter (`:596-652`) blocks `-enc`/`-EncodedCommand` but not PowerShell's accepted prefix spellings `-e`/`-ec`; it inspects only `word-word` cmdlet tokens, so aliases (`sc`, `ri`, `saps`, `iwr`), `[System.IO.File]::WriteAllText(...)`, `[System.Diagnostics.Process]::Start(...)`, `(Get-WmiObject …).Create(...)`, `& calc.exe`, `&$var` and `>` inside `-Command` all pass as "read-only". *Probe (two reviewers):* `run_shell_command("dir . &where cmd")` → success, second command executed; validator allows `powershell -e …`, `-Command "Get-Content x > C:\out.txt"`, `"[System.Diagnostics.Process]::Start('calc')"`; `>&` also slips the regex but has no cmd.exe payload (handle duplication, not redirection); `<&` is correctly refused. Independently, the git allowlist checks only `cmd_parts[1]`, so `git log --output=<path> --format=<anything>` is a near-arbitrary-content, arbitrary-path file write, and `wmic /output:` writes too (`:569-592`; *probe:* real file written). Gate, stated honestly: `run_shell_command` **is** confirmation-gated, so an interactive TTY user sees the raw string and must approve — what fails is the allowlist's *claim* of read-only safety, and the gate is absent under `GAIA_AUTO_APPROVE_TOOLS`, `auto_approve_gated_tools`, a session "always" grant on `dir`, or a skill's `shell:execute:*` grant. **Fix (two steps):** (a) now — treat any `&` as an operator, reject any unique prefix of `EncodedCommand`/`File`/`ExecutionPolicy`, refuse `[Type]::`, `.Method(`, `&`/`.` invocation and `$` inside `-Command`, refuse `--output`/`-o`/`/output:`/`/append:` as already done for `sort -o`; regression tests from the probe strings; (b) then — argv execution with an explicit built-in table (`cmd /c dir …` as argv), pipelines as chained argv; the `exec_cmd = command` path exists to preserve PowerShell/pipe quoting (`:952-953`) and `_UNIX_TO_WIN` (`:960-975`) is string surgery on it, so this is a larger change. Confidence High. Tracked: #2768 (audit of `ALLOWED_COMMANDS`, closest), #2785 (adjacent). Source 01, 03, crit.

**C5. `shell:execute:gh` skill grant ALLOWs `gh auth status --show-token` / `-t`, printing the GitHub credential unprompted** 🔒 — `src/gaia/skills/binaries.py:414-415` (`"auth": _gh({"status"})`, empty deny-list) lands the call in the ALLOW tier that `skill_grant_covers_call` exempts from confirmation. *Probe:* `gh auth status --show-token → allow`, `gh auth token → refuse`. Any loaded skill with `shell:execute:gh` (or a prompt injection in one) can dump the PAT into tool output for a `network:read` skill to exfiltrate. **Fix:** `denied_flags={"-t","--show-token"}` on `auth`; allow-list flags for read-only subcommands as the `pytest` policy does; also refuse `--web`/`--watch`. Confidence High. Tracked: none. Source 01.

**C6. Hub-supplied `artifact.filename` is joined onto the temp workdir unvalidated → pre-consent arbitrary file write from a hostile hub origin** 🔒 — `src/gaia/skills/install.py:210-217` + `hub.py:276-282, 412-414` (`destination.parent.mkdir(...); destination.write_bytes(payload)`). Runs before signature, tier, `--allow-experimental` and dangerous-grant gates; the SHA-256 in the same manifest does not help. *Probe:* `filename='../outside-marker.zip'` → written outside workdir; absolute path → written. Precondition: the manifest must come from an attacker-controlled origin — a compromised bucket, or `GAIA_HUB_URL` pointed elsewhere (`hub/catalog.py:72-73` honours it); the Worker's own publish-time `ARTIFACT_FILENAME_RE` means an ordinary publisher cannot do this, and the default hub is HTTPS. A broken defence-in-depth control, not a live exploit. The zip-*entry* traversal check exists and is tested; the archive *name* has none. **Fix:** reject any filename that is not a single safe segment or always download to `workdir/"bundle.zip"`. Confidence High. Tracked: none. Source 01, crit.

**C7. Fifteen file/RAG/vision tools read or write outside the `allowed_paths` sandbox — a sandbox that is on by default and that three docs call a production security control** 🔒 — the sandbox is not opt-in: `PathValidator.__init__` (`security.py:248-255`) and `ChatAgent.__init__` (`gaia_agent_chat/agent.py:253-256`) fall back to `Path.cwd()`, so every ChatAgent/GaiaAgent runs one. Six families bypass it: (a) `filesystem_tools.find_files(scope=<path>)` accepts any root (`_get_search_roots:1120-1156`, `scope="everywhere"` walks every drive) and never calls the mixin's own `_validate_path`; the docstring at `:52` claims "All path parameters are validated"; `tests/unit/test_filesystem_tools_mixin.py:656 test_scope_specific_path` asserts arbitrary-path scope as intended behaviour, so fixing this breaks that test. (b) `rag_tools.index_directory` (`:1954-2016`) never calls `_is_path_allowed`; the file's only two calls are in `index_document` (`:1259`) and `query_specific_file`'s auto-index (`:576`). (c) `RAGSDK.index_document` (`rag/sdk.py:2552`) contains no validator call at all — its first path touch is `_get_cache_path` (`:452-457`), whose `except (OSError, IOError)` swallows the `PermissionError` `_safe_open` raises and returns a `…_notfound.json` key; the PDF/PPTX/XLSX/DOCX extractors then hand raw paths to their libraries (`:722, 1012, 1601, 1737`); the tool-layer gates are `if hasattr(self, "_is_path_allowed")`, defined in exactly one place repo-wide (`gaia_agent_chat/agent.py:1161`), so any custom agent composing `RAGToolsMixin` (the documented pattern) has no check. *Probe (twice):* PDF outside `allowed_paths` → opened and paged (`EmptyPDFError`), TXT → "Access denied". (d) `vlm/mixin.py:139-159, 193-202` `analyze_image`/`answer_question_about_image` read any path (zero validator references in the file) and return the VLM's *description* — an exfiltration channel, not just a read. (e) Listing tools: `ChatAgent.list_files` (`:1359-1393`, bare `os.listdir`), and in `file_tools.py` `_read_access_error` is called at exactly four sites (`read_file`, `search_file_content`, `get_file_info`, `analyze_data_file`) and never inside `search_file` (incl. all-drives `deep_search`), `search_directory`, `browse_directory`, `list_recent_files`. *Probe:* `list_files` outside sandbox → 83 entries while `is_path_allowed()` is False. (f) Two writers with no `validate_write`, blocklist or confirmation: `dump_document` (`rag_tools.py:1828-1913`) writes attacker-influenced markdown to any *absolute* `output_path` (a `~` path resolves under CWD — `resolve()` does no `expanduser`); `take_screenshot` (`screenshot_tools.py:29-79`) writes PNG bytes to any path. Neither is in `TOOLS_REQUIRING_CONFIRMATION` (`agent.py:198-211`). Attacker position for all six: prompt-injected content steering tool arguments; no confirmation asked. **Fix:** one `FileAccessPolicy` enforced for every path-taking tool, validated in `RAGSDK.index_document` itself, `index_directory` per file, VLM/SD path args, every listing root, and both writers; narrow `_get_cache_path`'s handler to re-raise `PermissionError`; sequence the `hasattr` removal — attach a default `PathValidator([Path.cwd()])` at mixin registration first, *then* fail loudly on a missing validator, or every agent composing the mixin without one breaks; fix the pinning test. Confidence High. Tracked: #3316 covers only the `hasattr` inconsistency. Source 01, 08, crit.

**C8. A session's file allowlist silently expands to the whole directory an attached document sits in (`$HOME` included), reads have no sensitive-file denylist, and the write guard misses shell-rc / autostart / git-hook files** 🔒 — `src/gaia/ui/_chat_helpers.py:926-940` (`_compute_allowed_paths`) grants the **parent directory** of every attached document to a `prompt_profile="full"` agent with `read_file`/`write_file`/`edit_file` and shell tools; attach `C:\Users\alice\notes.txt` and the home tree is allowlisted for the turn. `PathValidator` applies no sensitive-file denylist on reads (`is_write_blocked` is reachable only from `validate_write`, `security.py:584`; `file_io_tools.py:54` gates reads on `is_path_allowed` alone), so `read_file("~/.ssh/id_rsa")` returns the key. On the write side, `security.py:29-52, 112-190, 495-560` cover `.env`, key material, `~/.ssh`, `LaunchAgents`, the Windows `Startup` folder — but not `~/.bashrc`/`.profile`/`.zshrc`/`.config/autostart/*.desktop`/`.gitconfig`/`.git/hooks/*`/PowerShell `profile.ps1`, and `_prompt_overwrite` (`security.py:622-640`) auto-approves overwrites when `_is_interactive()` is false, i.e. in the UI server context. A prompt-injected `write_file("~/.bashrc", "curl … | sh")` passes `validate_write`, shows a benign-looking modal (or none under auto-approve), and runs on the next shell — the cleanest injection → persistence chain in this report. A machine-global grant list compounds it (I13: `~/.gaia/cache/allowed_paths.json`, written by the CLI's `[a]lways`, is unioned into every validator incl. the UI's). **Fix:** grant the *files*, not their parents (`PathValidator` already matches exact paths); if a directory grant is needed, refuse `Path.home()`, drive roots and `BLOCKED_DIRECTORIES` ancestors; apply `SENSITIVE_FILE_NAMES`/`SENSITIVE_EXTENSIONS` to reads; add shell rc / profile / autostart / git-hook / PowerShell-profile names to the write blocklist; surface "this file runs on login" in the modal. Do this as the first step of the `FileAccessPolicy` work (C7) so it is not reverted by the refactor. Confidence High. Tracked: none (#2768 audits `ALLOWED_COMMANDS`, not the write guard). Source 03, crit.

**C9. `fetch_webpage` / `open_url` (ChatAgent inline tools in the flagship's default `full` profile) bypass the SSRF/private-IP guard the browser mixin enforces** 🔒 — `gaia_agent_chat/agent.py:1521-1566, 1495-1518`: bare `httpx.get(url, follow_redirects=True)` with only a scheme check, while `BrowserToolsMixin.fetch_page` goes through `WebClient`, which refuses loopback/private/reserved IPs and re-checks after DNS resolution (`web/client.py:45-75, 327-365`). `http://127.0.0.1:13305/…`, the daemon loopback API, `169.254.169.254`, and public URLs that 302 to localhost all get through. Attacker position: indirect prompt injection from an indexed document or fetched page. **Fix:** route through `WebClient` or delete the duplicates (`fetch_page` is registered in the same profiles). Confidence High. Tracked: none. Source 01, crit.

**C10. The generic `AgentServer` REST API (the server hub packages are documented to use for `--api`) has no caller auth and Origin-reflecting credentialed CORS; the OpenAI-compatible API has no auth on chat completions** 🔒 — `src/gaia/agents/base/server.py:441-447` (`allow_origins=["*"], allow_credentials=True` — Starlette reflects the requesting Origin in that configuration; *probe* confirmed browsers do not reject it), `run_api` (`:664`) binds `localhost:8000`, `agent_provision` (`:595-625`, `POST /v1/<id>/init`) can start multi-GB pulls. The repo's own `gaia.sidecar.caller_auth` (used by the flagship sidecar) documents exactly this drive-by/DNS-rebinding threat; the base class other agents inherit gets none of it. Any web page can `fetch("http://localhost:8000/v1/chat/completions", …)` and drive `process_query` (non-gated tools run; gated ones are denied off-TTY). `src/gaia/api/openai_server.py` gets CORS **right** (`_cors_config():158-189` is loopback-only by default and its `*` branch is opt-in with credentials disabled — an earlier draft of this finding said otherwise and was refuted); its real gap is auth: `/v1/chat/completions` has none (only the `/v1/<agent>/*` relay checks `GAIA_API_KEY`), the docs' first example binds `0.0.0.0` (`api-server.mdx:24`), and `gaia api --help` offers `--host` with no auth flag. **Fix:** copy `openai_server._cors_config()` into `AgentServer.build_api_app` verbatim (removes the reflection in one reviewed change), then mount `HostOriginMiddleware` + a dependency built on `caller_auth.token_ok`/`is_exempt_path`; apply `require_api_key` to chat completions when `GAIA_API_KEY` is set and refuse non-loopback binds without a key; fix the doc example. Confidence High. Tracked: #2951 (names `server.py:442-446` exactly), #630 (API auth). Source 01, 03, crit.

**C11. Agent UI backend: 41 of 92 mutating routes are CSRF-able from any website — one body-less cross-origin POST publishes the user's Agent UI to the internet; no Host/Origin validation anywhere** 🔒 — the `X-Gaia-UI` preflight guard is defined **four times** (`routers/connectors.py:106`, `agents.py:58`, `hub.py:53`, `memory.py:41`) and applied to 24 route decorators; `memory.py` applies its own copy to 3 of ~20 routes. Of the 92 mutating routes (incl. the 14 `/v1/email/*` routes `server.py:638-640` mounts unconditionally), 41 take no Pydantic body and are reachable by a plain cross-origin form POST or query-only request: `POST /api/tunnel/start` and `/stop`, `POST /api/documents/upload` (multipart → indexed into the user's RAG = persistent prompt injection), `POST /api/files/upload`, `POST /api/documents/{id}/reindex`, `/cancel-indexing`, `POST /api/memory/prune?days=7` (deletes memory older than 7 days), `/consolidate`, `/rebuild-embeddings`, `/rebuild-fts`, `/reconcile`, `/refresh-system-context` (runs `store.delete_by_category("system")` and re-scans the host), `POST /api/sessions/{id}/activate`, `POST /api/mcp/agent-server/stop`, and the whole `/v1/email/*` surface (`send`, `draft`, `archive`, `quarantine`, `triage`, `confirm`, `init`, `search`…). Pydantic-JSON-body routes are protected only *incidentally* — FastAPI 422s a `text/plain` body (verified live) — which is not a security control: `mcp.start_agent_mcp_server` already takes `Optional[...] = None`, and DELETE/PUT/PATCH routes without the guard are protected only by the preflight non-simple methods require. *Live proof:* a body-less cross-origin `POST /api/tunnel/start` from a probe returned 200 **and started a real public ngrok tunnel** (killed immediately); a cross-origin form POST to a mirror of `prune_memory` returned `{"pruned":7}`. `grep TrustedHost|allowed_hosts src/gaia/ui src/gaia/daemon src/gaia/api` → none, so DNS rebinding also reaches the read side (`GET /api/files/preview?path=~/.ssh/id_rsa` — the endpoint whose token-scoped variant is I34). By contrast `routers/connectors.py` carries the guard on 100 % of its mutating routes, which is what makes `memory.py` an oversight. **Fix:** one middleware enforcing the header on every non-GET `/api|/v1` request (exempt only the OAuth loopback callback GET) — inventory non-browser clients (Electron shell, TUI daemon client, `gaia mcp`) first so they send it; `TrustedHostMiddleware` + `Origin` allowlist; collapse the four guard copies; `APIRouter(dependencies=[...])` defaults so a new route cannot ship unguarded; a route-table introspection test. Confidence High. Tracked: none. Source 03, crit.

**C12. The Agent UI backend trusts every `*.ngrok-free.app` and `*.use.devtunnels.ms` origin with credentials and `allow_headers=["*"]` — anyone can rent one, and it defeats the `X-Gaia-UI` guard C11 relies on** 🔒 — `src/gaia/ui/server.py:549-563` (`allow_origin_regex=r"https://[a-zA-Z0-9-]+\.(ngrok-free\.app|use\.devtunnels\.ms)"`, `allow_credentials=True`, `allow_headers=["*"]`). Those are shared self-service namespaces: an attacker's page on their own free subdomain is an origin this backend trusts, its preflight is approved *including `X-Gaia-UI`*, so it reaches the 24 guarded routes as well as the 41 unguarded ones and can **read** every response — `GET /api/files/preview?path=…` included. `TunnelAuthMiddleware` passes every request through when the tunnel is not active (`:123-125`), so there is no cookie to ride and no auth to defeat. *Probe (exact middleware config, starlette 1.6.0):* preflight from `https://attacker-owned.ngrok-free.app` → 200, `ACAO=<that origin>`, `ACAC=true`, `ACAH=x-gaia-ui,content-type`; read-back of `/api/files/preview` → 200; `https://x.ngrok-free.app.evil.com` → 400 (the regex is full-matched — that half is fine). The allowance is also dead config: the tunnel GAIA starts issues `*.ngrok-free.dev` (which the `.app` regex does not match), and the mobile flow serves the SPA *from* the tunnel origin, so its requests are same-origin and CORS never applies — the entry grants a capability to attackers and nothing to users. Browser Private-Network-Access enforcement is not a mitigation (not shipped consistently; Starlette emits no PNA header). An earlier draft cleared this in Appendix C on the grounds that ngrok domains are on the PSL — which protects the *cookie*, not the API. C11's middleware fix is insufficient without this. **Fix:** delete `allow_origin_regex` (nothing needs it); if a tunnel origin must be allowed, allow the one URL `TunnelManager` minted for this session; test that `https://someone-else.ngrok-free.app` gets a 400 preflight. Confidence High. Tracked: none (#2951 is about two other servers). Source crit.

**C13. MCP bridge answers every origin with `Access-Control-Allow-Origin: *` and runs unauthenticated by default** 🔒 — `src/gaia/mcp/mcp_bridge.py:436-443, 453, 505`; `gaia mcp start` defaults to "Auth: none". *Probe (live):* `OPTIONS /chat` with `Origin: http://evil.example` → 200 + `ACAO: *`. A page can POST to `/chat` and **read** the reply, including the one shared `AgentSDK` conversation every caller uses (`:173-182`) and any RAG context. `tests/unit/test_mcp_bridge_auth.py:227` pins the open preflight as intended. `resolve_bind_host` (`:468-495`) keeps the bridge on loopback unless the user passes `0.0.0.0`, but loopback is not a mitigation here — the attacker is a page in the user's own browser reaching `http://localhost:<port>`, and `ACAO: *` is exactly what lets it read the answer. **Fix:** reflect only allow-listed origins (or none) when no token is configured; drop `ACAO: *` from data responses; per-client sessions; flip the test. Confidence High. Tracked: #2951 (adjacent), none for the bridge. Source 03.

**C14. Electron: unvalidated `shell.openExternal` + a renderer link allow-list that passes `/…` and `//host/…` — one click on an LLM-rendered link can launch a local binary or a UNC path** 🔒 — `src/gaia/apps/webui/main.cjs:515-518` (`setWindowOpenHandler(({url}) => { shell.openExternal(url); …})`, no scheme check, no `will-navigate` guard), window loaded from `file://` (`:569-571`); `src/utils/markdown.ts:52,56` lets root-relative/scheme-less URLs through; every markdown link is `target=_blank` (`MessageBubble.tsx:676-687`). `/Windows/System32/calc.exe` resolves to `file:///C:/Windows/System32/calc.exe` → ShellExecute; `//attacker/share/x.exe` (and the `\\host\share\x.exe` backslash form) → SMB fetch. *Verified:* `new URL('/Windows/System32/calc.exe', 'file:///C:/…/index.html')` returns exactly that on ada/WHATWG (Node 22), and `ShellExecuteW` on those URLs answers `SE_ERR_FILENOTFOUND` (it resolved them to paths), not `SE_ERR_NOASSOC`. Attacker position: prompt-injected model output plus one user click — not drive-by. This is the prompt-injection model #976's markdown hardening was written for. **Fix:** allow only `http:`/`https:`/`mailto:` in `main.cjs`, checked on the *resolved* URL Electron hands the handler (resolution is what turns `/x` into `file:///C:/x`); add `will-navigate` prevention; keep only `#` fragments for chat-content links. Confidence High (the one untested link is whether Electron 44's `openExternal` itself filters `file:` before `ShellExecuteW`). Tracked: none (#976 is the ancestor). Source 04, crit.

**C15. Agent UI "Always allow this tool" is persisted forever in `localStorage`, keyed by tool *name*, auto-approved client-side with `remember=false`, with no UI to revoke** 🔒 — `stores/notificationStore.ts:22,109-117`, `ChatView.tsx:791-802, 824-833`. **C16. (b) The `remember` tool's `VALID_CATEGORIES` (`:2550`) admits `system`/`profile`/`permission` while its docstring lists six. (c) `ui/routers/memory.py:1557, 1584` (`commit-discovery`/`commit-inference`) pass `item.get("category","profile")` straight to `store()`; the module header claims all validation sites are "in sync automatically". `_build_stable_memory_prompt` renders these rows first in every later prompt — persistent prompt injection and, via `permission`, self-granted autonomous-mode approval; reachable from indirect injection in an indexed document. **Fix:** validate categories in `MemoryStore.store()`/`update()` (reject privileged ones unless the caller is `seed_bulk`/admin); align `remember`; route the two routers through `KnowledgeCreate`.
