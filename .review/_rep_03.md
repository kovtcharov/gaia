## 3. Important findings (🟡)

Compressed to what a maintainer needs to act; the raw reports and `_crit_*` verification logs carry the quoted evidence. "Tracked" is omitted where no open issue was found. Items the verification pass demoted to 🟢 moved to §4.

### 3.1 Agent framework, tools, memory, skills

- **I1. `@tool` silently overwrites same-named tools — the flagship registers three `read_file`s, two `browse_directory`s (different signatures) and two `search_web`s; the last wins.** `tools.py:79-87` (no collision check); `profiles.py:45-50` order file → filesystem → file_search → file_io. Verified effects: the sandboxed, 50 MB-capped filesystem `read_file` (`filesystem_tools.py:27 MAX_READ_BYTES`) is replaced by `file_io.read_file`, which has no size cap at all and dereferences `path_validator` unguarded (#3316); with `PERPLEXITY_API_KEY` set, "search_web (DuckDuckGo, no key)" silently becomes a paid cloud call while the prompt still says DuckDuckGo. Fix: `tool()` raises on re-registration with a different function; one `read_file`/`browse_directory`; rename the Perplexity tool; registry-shadowing test.
- **I2. `AgentSDK.send()` sends the system prompt twice and `update_config(system_prompt=…)` leaves the old one in place** — `chat/sdk.py:100-110, 518-539`; provider prepends `_system_prompt` and `send()` embeds it again in hand-rolled `<start_of_turn>system` tokens. *Probe:* `count of SYS-ONE across request: 2`. Fix: structured messages via `llm_client.chat`.
- **I3. `AgentSDK._enhance_with_rag` silently falls back to a non-RAG answer; `send`/`send_stream` desynchronise history on error** — `sdk.py:1168-1172, 526, 600`. Corrupt FAISS → confident ungrounded answer with no signal (a "No Silent Fallbacks" violation); Lemonade restart mid-turn → dangling duplicate `user:` turn forever. Tracked: #3315 (tool-layer twin only).
- **I4. `list_recent_files` returns every match with no output cap** (`file_tools.py:2598` def; `:2732-2762`, where a "Return all files …" comment makes it a design decision rather than an oversight) → context overflow on the 32K NPU profile with OneDrive.
- **I5. Bundle-vs-hub `SKILL.md` consistency check compares only `name`/`security_tier`/`permissions`, not `metadata.gaia.tools`/`version`** (`skills/install.py:418-422`) — the install-time "instruction-only, ships no code" warning can misdescribe what gets imported. Gated behind `--allow-experimental`; the signature itself still binds every file. Medium on exploitability.
- **I6. Memory extraction "timeout" does not bound latency** — `memory.py:1393-1402` `future.result(timeout=…)` inside a `with ThreadPoolExecutor` → `shutdown(wait=True)`; the turn waits for the full LLM call then discards the result (*probe:* 3 s task, 0.5 s timeout → 3.00 s elapsed). Docstring says 3 s; the constant is 8 (`:189` "raised from 3 to 8").
- **I7. Hybrid memory search drops FAISS hits outside the top-200-by-confidence pool** (`memory.py:1221-1236`; pool is `ORDER BY confidence DESC`) — rich-get-richer; low-confidence but relevant facts are only reachable via BM25.
- **I8. Date-only `time_to` silently drops the whole final day from `recall`** — lexical compare `'2026-03-31T15:00:00-07:00' > '2026-03-31'` at `memory.py:1254, 2782` and `memory_store.py:1580`; the tool docstring's own example (`memory.py:2661`) is the broken shape, so this is the *normal* call. *Probe:* `time_to='2026-03-31': 0`, `'2026-04-01': 1`. Wrong data through a documented call — top of this section.
- **I9. Memory misc:** memory-disabled sessions log a spurious WARNING on every prompt build (`hasattr` guard passes on `None`; `:1985-1992, 3033-3034`); `reset_memory_session` raises; `GoalStore` (`goal_store.py:416-452`) enforces none of the state machine its docstring promises (`approve_goal` re-queues rejected/completed goals; typo'd statuses are stored).
- **I10. Flagship `GET /v1/gaia/init` reports "Lemonade not reachable" when `LEMONADE_BASE_URL` uses the documented `/api/v1` form** — `hub/agents/gaia/python/gaia_agent/server.py:370-385` appends `/api/v1/models` to the raw value (→ `/api/v1/api/v1/models` 404; *probe* reproduced); `readiness.resolve_probe_base` already normalises both forms. TUI preflight blocks while `curl …/health` is 200. Tracked: #3203.
- **I11. `session_registry.delete()` closes an agent without claiming `run_lock`** (`gaia_agent/session_registry.py:276-283`, contradicting the class docstring; no production caller yet). (The `scan_all` unknown-source silent drop is latent — no CLI surface passes `sources` — and is in §4.)
- **I12. SDK docs say default `max_steps` is 20; the framework default is 50** (`docs/sdk/core/agent-system.mdx:365,465,785` vs `agent.py:105 DEFAULT_MAX_STEPS`); the doc's `process_query` walkthrough no longer resembles the loop.
- **I13. The "session-scoped" allowlist silently unions a machine-global, CLI-written grant list** — `security.py:271` `_load_persisted_paths` (called unconditionally from `PathValidator.__init__`) merges `~/.gaia/cache/allowed_paths.json`, which the CLI writes whenever a user answers `[a]lways`; `_chat_helpers.py:927`'s docstring claims the opposite. One "always" at a `gaia chat` prompt for `C:\work\clientA` grants every later Agent UI session read+write there, with no expiry and no revocation UI — the same standing-grant shape as C15 on a different surface, compounding C8. Fix: `load_persisted=False` for host-supplied allowlists (`registry.py:138` already treats `allowed_paths` as security-relevant).
- **I14. The Tavily API key is handed to any caller with no grant check — and stays ungated even after C1 is fixed** — `web/tavily.py:125,145` passes neither `agent_id` nor `required_scopes` to `connectors/handler.py:137-168`, which skips the grant check when either is missing; `test_handler.py:161` locks it in. Contradicts `docs/security/connections.mdx:37,63`. Local only (a paid-search key; the connectors threat model treats in-process code as trusted). Fix at the call site: `agent_id=` + `required_scopes=["use"]`; default `required_scopes` for `mcp_server` specs.

### 3.2 LLM layer, installer, CLI

- **I15. NPU users get the GPU model downloaded and loaded on every cold start** — `LemonadeManager.ensure_ready` (`lemonade_manager.py:729-732, 797-847`) preloads `DEFAULT_MODEL_NAME` (Gemma-4 GGUF) whenever the server is idle; `gaia init --profile npu` deliberately never downloads it (`init_command.py:1660-1664`) but `_verify_setup` (`:1955`) excludes only `sd`, so init's "Run model verification?" step (default **yes**) pulls ~3 GB of Vulkan model on an NPU box, then FLM loads on top (the #1676 thrash class). A dev box with a resident model never sees it. Fix: resolve the preload model from the device profile; same `("sd","npu")` exclusion in `_verify_setup`. Tracked: #1676 (related).
- **I16. `gaia init` pins Gemma-4 to a 32K window that the runtime immediately reloads to 64K** — `INIT_PROFILES[*].min_context_size = 32768` (`init_command.py:92,102,154`; `:140` is the NPU profile, where 32768 is correct) with `save_options=True` (`:1791-1798`) vs `GPU_CTX_SIZE = 65536` (`lemonade_client.py:173,334`) → first `gaia chat` after init does a full ~100 s reload; `test_init_ctx_size.py:116-122` pins the literal. Fix: one `ctx_for(device)`.
- **I17. `check_model_loaded()` checks "downloaded" (substring match on `/models`), and init's verify step then calls a global `unload_model()`** (`lemonade_client.py:4155-4175`, `init_command.py:1788-1789`) → init globally unloads whatever is resident before each LLM test (a wasted cold reload of the model `ensure_ready` just preloaded; on the `all` profile, whose model order is a `list(set(...))`, it can also evict the embedder).
- **I18. Context-overflow on the NPU profile is mis-classified as retryable and re-sent once** — `providers/lemonade.py:237-245` and `_chat_helpers.py:236-244, 1610-1625` compare `n_ctx` to the GPU literal 65536; NPU ceiling is 32768, so a genuine overflow is retried identically and the user reads "Reloading the model" instead of "start a fresh task". Tracked: #2884.
- **I19. `VLMClient` rewrites `https://…` and any path prefix to `http://host:port/api/v1`** (`vlm_client.py:101-110` → `LemonadeClient(host=,port=)` branch at `:995-999`) — remote/ngrok `LEMONADE_BASE_URL` breaks every vision call; the resulting connection error is then returned as page text (I20).
- **I20. VLM extraction failures are returned as document text (`"[VLM extraction failed: …]"`) instead of raised** (`vlm_client.py:203-207, 281-282, 290-291`; zero callers check the prefix; flows into `rag/sdk.py:825, 1186`, `vlm/mixin.py`, `providers/lemonade.py:505`, `messaging/ingest.py:30`) → error strings get chunked, embedded and quoted back as answers. `vlm/structured_extraction.py:306, 445, 469` turn unparsable output into `[]`/`{}`/`0.0` and `:200-231` sums the zeros into `timeline_totals`; the unit tests pin this as the contract. The strongest "No Silent Fallbacks" violation in this section — a confident wrong answer, gated only on a VLM failure.
- **I21. `.env.example:14` sets `LEMONADE_BASE_URL=http://localhost:8000/api/v1`** — the pre-10.1 port; `DEFAULT_PORT` is 13305. Breaks every command run from a directory under the copied `.env` (`load_dotenv()` is CWD-relative).
- **I22. `create_lemonade_client()` / `initialize_lemonade()` (public SDK factories) ignore `LEMONADE_BASE_URL` and force `http://`** (`lemonade_client.py:4573-4592, 4692-4723`); no in-tree production caller (only `__main__` and the client's own tests), but the docstring example + `auto_start=True` would target `localhost:13305` and `kill_process_on_port` any non-healthy occupant. `.claude/skills/lemonade-client-patterns` wrongly claims the CLI uses the factory.
- **I23. The Lemonade MSI/PKG is authenticated only by TLS to github.com — GAIA pins a SHA-256 for its own embedded server and sidecar but not for the third-party installer it runs elevated, in both the runtime installer and the signed Windows installer build** — `lemonade_installer.py:440-461` (download), `:602-638` (`msiexec /i` elevated), `:742-752` (`sudo installer -pkg`); `verify_download_url` is a HEAD availability probe; `.github/workflows/build-installers.yml:334-356` fetches the MSI with only a `>1 MB` size guard and the "verify embedded" step (`:444-463`) is a filename check that warns-and-passes when 7z cannot read NSIS solid compression; `lemonade-version-bump.yml` auto-bumps the version on a schedule. Defence-in-depth against a third-party compromise, not a live defect — the top 🟡 in this group. - **I24. ### 3.3 Servers, daemon, connectors, security

- **I34. The tunnel token is a full read token for the user's entire home directory** — `ui/routers/files.py:509 preview_file` (any extension `< 1 MB`, 200 lines × 500 chars — enough to contain an ed25519 or RSA private key), `:150 browse_files`, `:606 serve_local_image`; the only containment is `ensure_within_home` (`ui/utils.py:391`). `GET /api/files/preview?path=~/.ssh/id_ed25519` with the bearer returns the key; `~/.gaia` credential stores are listable. Docs pitch the tunnel as mobile chat. The token must be held (scanned QR / cookie on a lost phone) — the credential-free variant of this read is C11's DNS-rebinding side. Fix: sensitive-roots denylist shared with `security.PathValidator` (or a positive allowlist), restrict preview to `TEXT_EXTENSIONS`, document what a tunnel token grants. 🔒
- **I35. MCP-server secrets skip the insecure-keyring refusal the OAuth path enforces** — `connectors/mcp_server.py:168, 215, 261, 334` call `keyring.*` directly; a headless Linux box with `keyrings.alt` writes a GitHub PAT to `keyring_pass.cfg` in cleartext while `docs/security/connectors.mdx:21-25` says every save is refused. Local only. 🔒
- **I36. Filesystem index: latent sibling-deletion and FTS5 syntax bugs, currently masked by a silent fallback** — `filesystem/index.py:349-354, 371-375` `LIKE '<root>%'` without separator/escape (*probe:* scan `docs` then `doc` → `docs/b.txt` removed) — but `scan_directory` has zero callers, so it is latent; `query_files(name=…)` (`:707-710`) passes LLM text as a raw FTS5 `MATCH` (*probe:* `c++`, `"report (final)"` → syntax error; `name:report OR path:secret` runs as a column query) — but the only caller (`filesystem_tools.py:663`) wraps it in `except Exception: logger.debug(...)` and silently falls back to a full filesystem walk (`:686-689`), and routes any query containing `(` away from the index entirely. The silent fallback is the live defect.
- **I37. Non-streaming `/v1/chat/completions` blocks the whole event loop** (`openai_server.py:364`, sync `process_query` inside `async def`; the streaming branch 130 lines below already uses `run_in_executor` — a one-line asymmetry).
- **I38. MCP bridge:** `/chat` is one shared conversation for every caller (`mcp_bridge.py:173-182`); with `--verbose` off (the default) `log_message` (`:464`) does `"/health" not in args[0]` where `args[0]` is an `HTTPStatus` → `TypeError` before the error response is written, so any unsupported method or malformed `Content-Length` (`:344`, bare `int()`) drops the connection with no HTTP response (*probe* reproduced); default `--base-url` and `mcp.json:342` ignore `LEMONADE_BASE_URL`; `/status` and `/llm` error bodies leak `str(e)`; unbounded POST body.
- **I39. `gaia telegram start --background` never polls** — daemon threads die with the CLI; PID file holds a dead PID (`telegram.py:313-337`). Tracked: #3133. **Port map:** the MCP bridge (`gaia mcp start`) defaults to 8765 (`cli.py:2383`), `gaia mcp serve` (Agent UI MCP) to 8766 (`cli.py:2490`) while `agent_ui_mcp.py:42` sets its own module default to 8765, `gaia mcp tui` to 8767; the Telegram health server hard-codes `127.0.0.1:8765` (`telegram.py:308`) — a three-way collision — and `tui_mcp.py:95`'s comment has bridge/agent_ui swapped. (`--health-port` and `stop --force` are dead flags — C34.)
- **I40. `gaia schedule add` accepts an invalid cron; every later `list`/`show`/`run`/`daemon` then crashes** (`schedule/store.py:41-49` + `cli.py:3071-3079` no validation; crash sites `daemon.py:85-88` from `cli.py:3090, 3105, 3127`; *probe* reproduced). **`schedules.toml` writes are not atomic and CLI/daemon race on it** (`store.py:126-130`; the daemon rewrites after every fire and reads only at start). **The Telegram sink accepts a bot token hand-written in cleartext in `schedules.toml`**, and both the error message (`sinks.py:100-105`) and `cli.mdx:2412` present that as a supported option (GAIA itself never writes the token).
- **I41. The UI scheduler computes fixed-time schedules in UTC** — `ui/scheduler.py:564-576` `datetime.now(timezone.utc).replace(hour=…)` with no tz conversion, so "daily at 9am" fires at 09:00 UTC (01:00–02:00 for a Pacific user) — 100 % reproducible for every non-UTC user; it also double-computes windowed `next_run_at`. Top-ranked 🟡 in this section; a candidate for 🔴 on the normal-use test (consequence is a mistimed job, not data loss). Fix: store an IANA tz; compute once.
- **I42. Three schedulers coexist with different semantics and no shared ledger** — `src/gaia/schedule/` (APScheduler/TOML), `ui/scheduler.py` (asyncio timers, SQLite), `daemon/scheduler/` (`DaemonClock`, exactly-once); `reconcile_jobs` runs only for the email adapter; "daily at 9am" in the UI + `0 9 * * *` in the CLI fire unaware of each other. Tracked: #2156/#2379 (daemon clock).
- **I43. Daemon hygiene (local-only, same user):** re-ensuring a crashed sidecar leaves the previous launch-secret file on disk with a still-valid token (`daemon/sidecars/manager.py:674-691, 589-634`; `auth_token` minted once per manager; *probe:* `FIRST STILL ON DISK AFTER RE-ENSURE: True same token: True`); the custody secret (`/host/v1` read/write to memory, sessions, RAG, audit) is always delivered via bare process env even on the "file" leg (`:463-470` vs `:540-587`), inherited by sidecar children, and sidecars inherit `{**os.environ}` incl. the user's `ANTHROPIC_API_KEY`/`GITHUB_TOKEN` (`:448`; listed as a threat in `security-model.mdx:361-368`); on Windows only the launch-secret file gets the owner-only DACL — `instance.json` (daemon client token) and the sidecar ledger, the two confirmed `atomic_write_json` callers, get inert `0600` (`paths.py:99-132` vs `manager.py:113-193`); the v0→v1 custody migration (`daemon/migrate.py:243-263`) copies legacy DBs to paths `CustodyStore` never reads.
- **I44. `POST /v1/connections/{provider}` persists OAuth secrets before validating the provider** — `ui/routers/connectors.py:1082` → `connectors/api.py:543-550`: `save_provider_credentials` at step 4, `get_provider` at step 5 raises a bare `KeyError` for an unknown id → flat 500; a typo'd provider writes the real `client_secret` into the OS keyring under `provider:<typo>` and nothing clears it, while the function's comment asserts "the failure path must leave the keyring untouched".
- **I45. A consent prompt can drop a destructive argument behind a bare ellipsis** — `ui/sse_translation.py:643-644` caps the whole rendered invocation at `INVOCATION_TOTAL_CHARS = 1200` (`:618`) with a bare `"…"` (the exact thing the comment six lines above forbids), and arguments render in `sorted()` order, so `{"command": "<1200 chars>", "yes_delete_remote": true}` shows the user a plausible command and never the flag; the module docstring promises "every argument name is shown". - **I46. `ui/routers/memory.py` concentrates 18 fail-loudly violations**, two worse than the rest: `:763` `trigger_reconciliation` catches an agent-path failure and silently runs the standalone implementation instead (the "try the other provider" glue CLAUDE.md names); `:1578/:1616` `commit_discovery`/`commit_inference` swallow per-item failures at `debug` and return `{"stored": 7}` when the user approved 10. (This file was never in the coordinator's silent-swallow inventory, which named `system_context.py` as densest.)
- **I47. Browser history reaches the profiling LLM undelimited, and the approved output lands in the system prompt** — `ui/routers/memory.py:1301 stream_inference` concatenates scanner output (browser domains and page *titles*, app names, filenames) into `_INFER_PROMPT` (`:1114-1145`) with no fencing; on approval `commit_inference` stores `category="profile"`, which `agents/base/memory.py:2026-2031` renders into the system prompt. - **I48. `GET /api/connectors/agent-mcps` returns MCP `command` + `args` verbatim** (`connectors.py:616, 672-683`; `env` is correctly excluded) — MCP servers routinely carry credentials as CLI arguments (`--api-key sk-…`), on an unguarded GET, one function away from deliberate masking. Medium confidence (depends on how `mcp_servers.json` was written).
- **I98. Tunnel auth is fail-open during the first seconds of every tunnel start** 🔒 — `ui/server.py:126-128` gates the token check on `tunnel.active`, which requires `self._url is not None` (`tunnel.py:303-310`), set only after `_poll_ngrok_api()` (`:589-608`, called at `:420` — 0.5 s polls, up to 15 s); ngrok forwards traffic as soon as its control connection is up. Not reachable today: no shipped code path passes `domain=` (`ui/server.py:576` constructs `TunnelManager(port=…)` only), so the hostname is a random ngrok subdomain nobody can predict during the window — it becomes reachable the moment a custom domain is wired up, which the `domain` parameter exists to allow. Also: `_kill_stale_ngrok` (`tunnel.py:520-535`, unconditional at `:391`) `taskkill /f /im ngrok.exe` / `pkill -x ngrok`s every ngrok on the machine on every start — a developer's unrelated `ngrok http 3000` dies when they click "Start tunnel".

### 3.4 RAG, data, code index

### 3.13 Hub Worker, website router, website, install scripts

- **I90. Catalog writes are unconditional read-modify-write** — `workers/agent-hub/src/storage.ts:211-225`, `publish.ts:338, 470-474`, `catalog.ts:379-429 rebuildIndex`: no `onlyIf: { etagMatches }`, no serialisation. `release_components.yml` runs the `terminal-hub` and `agent-ui` publish jobs in parallel; an interleaving loses an entry from `index.json` (recoverable via `POST /reindex`, `index.ts:62-83`).
- **I91. Inline publish is not atomic** — artifact `put` first, then up to 8 doc objects, the manifest, and a ~40-call index rebuild (`publish.ts:361-474`, same shape in `skill-publish.ts`); any failure after the artifact `put` returns 500 but leaves the object; on retry `publish_to_r2.py:372-397` reconciles the 409 by byte-comparing the stored object, reports `OK 409 … identical bytes`, and the job goes green with the binary missing from `manifest.json`/`index.json` and from `gaia agent install`; recovery is manual R2 deletion.
- **I92. Artifact filenames can collide with the per-version doc objects** — `multipart.ts:20 ARTIFACT_FILENAME_RE` (enforced at `publish.ts:313` / `skill-publish.ts:110`) forbids only separators, so `gaia-agent.yaml`, `README.md`, `SKILL.md`, `package-files.json`, `audit.json` pass and are overwritten by the doc writes that follow (`publish.ts:413`); the catalog records the artifact's original SHA-256, so installers download the YAML and abort on checksum mismatch. Authenticated publishers only — a foot-gun that breaks the "server-side SHA-256 you can trust" guarantee.
- **I93. Both published schemas are stale.** `manifest.schema.json` has `language` enum `["python","cpp"]` and no `type` property under `additionalProperties: false`, so three of the four live manifests fail it (`terminal-hub`, `agent-ui`, `gaia`); `index.schema.json`'s `skill_metadata.audit` lacks the `attestation`/`cleared_tiers`/`content_digest`/`manifest_digest` the Worker emits, so it will reject every skill entry the moment the first skill is published (live `index.json` validates today only because none has); the conformance test diffs top-level keys only; the README calls both "the contract the website Hub pages build from".
- **I94. The install one-liners are served by an out-of-repo Cloudflare redirect to GitHub `main`** — `curl -I https://amd-gaia.ai/install.sh` → 302 to `raw.githubusercontent.com/amd/gaia/main/installer/scripts/install.sh`; `website-router/src/index.js` has no such rule and both READMEs say every non-`/docs` path is proxied to the Astro site. Users always execute whatever is on `main` at that second (no tag pinning, no rollback), and the rule is invisible to whoever rotates the zone — it has already 404'd once (#778, closed). The trust boundary is the project's own repo over HTTPS, so this is release-integrity hygiene rather than a third-party supply-chain hole; the genuine third-party link is the unpinned `astral.sh/uv` fetch in both scripts (I67). Tracked: #778.
- **I95. website-router's documented HTML edge cache is not happening in production** — README promises 60 s HTML / 1-year asset TTLs; live every HTML request is `cf-cache-status: DYNAMIC` and the origin sends no `Cache-Control` at all (only `etag` + `vary`), so assets get the zone's default 4 h Browser Cache TTL rather than the Worker's `ASSET_CACHE_TTL` (*probe*). Every page view round-trips to Railway.
- **I96. The flagship's live hub page tells visitors to `pip install gaia-agent-gaia`, which does not exist** — `website/src/data/catalog.ts:548-555` adds a "pip" tab for any `type: agent` with `language: python` and no `npm_package`; the flagship is published only as frozen binaries and *no* Python agent wheel is published at all (`publish_agents.yml` is `if: false` pending #1179). *Probe (live):* the page carries `pip install gaia-agent-gaia`; PyPI → 404. The primary CTA (`gaia agent install gaia`) is correct, so the impact is one tab of three, failing loudly. The same `installMethods()` was fixed twice for the mirror case (#3147/#2969) without adding the artifact-kind gate that would cover both. Fix: publish the wheels or stop advertising pip; gate the tab on an `artifact_kinds` field. Tracked: #3101 (same root cause), #1179.
