# Flagship GAIA installer

One-click installer for the flagship GAIA agent: the Go terminal UI plus the
frozen Python agent, with Lemonade Server installed during setup. A user
downloads one file and ends up with a working agent — no repo clone, no Python,
no Node, no venv.

This is a **separate artifact** from the Electron Agent UI installer
(`installer/nsis/`, `src/gaia/apps/webui/electron-builder.yml`), which ships a
different product and is generated by electron-builder. Nothing here is shared
with it: the structure was copied, not parameterized, so a change to one cannot
break the other.

| Path                | What it is                                              |
| ------------------- | ------------------------------------------------------- |
| `build.ps1`         | The Windows build — stages a verified payload, packs it |
| `nsis/installer.nsi`| The NSIS script                                          |
| `nsis/pathmgr.ps1`  | Per-user PATH edits, used by install and uninstall       |

## Build it

```powershell
.\installer\tui\build.ps1
```

That produces `dist-installer\gaia-<version>-x64-setup.exe`. Requires
[NSIS](https://nsis.sourceforge.io/Download) (`winget install NSIS.NSIS`) and
Node (for `npm pack`, which is how the lock is fetched).

To bundle binaries you built yourself instead of the published ones:

```powershell
.\installer\tui\build.ps1 `
  -SidecarPath .\hub\agents\gaia\python\packaging\dist\gaia-agent.exe `
  -TuiPath     .\tui\bin\gaia-tui.exe
```

## What gets verified

`binaries.lock.json` from the published `@amd-gaia/gaia` package is the source
of truth for what a release contains and what it hashes to. Every binary
downloaded from the hub is SHA-256 checked against it **before** it is staged; a
mismatch stops the build rather than producing an installer nobody can vouch for.

Locally-built binaries are staged as-is and reported as `UNVERIFIED`, because
there is nothing published to compare them against. That is the developer path —
CI always takes the lock path.

## Bundled, not fetched

The binaries ship inside the installer (~57 MB) rather than being downloaded
during setup. Same call the Agent UI installer makes, for the same reasons: the
install works offline, and it cannot strand a user with shortcuts pointing at
binaries a mid-install network failure never delivered. The trade is a larger
download; the update path (`gaia-tui update`) is where fetch-and-verify belongs,
because there a failure leaves the working install untouched.

## What it installs

Per-user, into `%LOCALAPPDATA%\Programs\GAIA` — no elevation prompt.

- `gaia-tui.exe`, `gaia-agent.exe`
- Start Menu and Desktop shortcuts
- The install directory on the user's `PATH`. This is load-bearing, not a
  convenience: the terminal UI resolves `gaia-agent` with `exec.LookPath`, so
  the PATH entry is how it finds its agent at all.
- Lemonade Server, from the bundled MSI

PATH edits go through `pathmgr.ps1` rather than NSIS registry writes: a stock
makensis caps strings at 1024 characters, so reading a longer PATH into a
register and writing it back silently truncates it.

## Updates

The installer is the first install; `gaia-tui update` is every one after it.
It reads the published lock, asks before downloading, SHA-256 verifies, and swaps
both binaries in place — see `tui/internal/update/`. It resolves the sidecar the
same way the terminal UI does, so it updates the copy this installer placed
rather than the daemon's cache.

`gaia-tui update pin <version>` holds a machine on a specific release (downgrade
included) until `gaia-tui update unpin`.

## Why Windows only

Windows is where a terminal program has no good install story and where the AI PC
target lives, so it gets a real installer. macOS and Linux already have the
one-liner (`installer/scripts/install.sh`), which is the idiomatic shape there and
handles PATH and shell startup files.

**Known gap:** `install.sh` installs `gaia-tui` but not `gaia-agent`, so the
flagship's direct-spawn path has no binary on those platforms. Closing it means
fetching the sidecar from the same lock this build uses and verifying it the same
way. A `.dmg`/`.deb`/`.AppImage` is deliberately *not* the answer — those exist
for the Electron Agent UI because it is a GUI app; a terminal program does not
need a bundle format.

## Uninstall

Removes the files, both shortcuts, the PATH entry, and both registry keys. It
asks before removing `~/.gaia` and defaults to keeping it, so chats, memory, and
skills survive unless the user opts in. Lemonade is deliberately left installed —
it is an independent Windows product, removed the same way whether it arrived
from this bundle or a standalone download.
